# DB 마이그레이션 규칙 (Flyway 등을 쓰는 프로젝트)

- 스키마 변경은 마이그레이션 파일로만 한다. 운영 DB 를 손으로 고치지 않는다.
- 파일명: `V{버전}__{설명}.sql` (밑줄 두 개). 설명은 명사형으로 짓는다. 예: `V26__add_users_phone_number.sql`
- **한 번 적용된 파일은 수정하지 않는다.** 체크섬이 달라져 기동이 실패한다. 고칠 일이 생기면 다음 버전 파일을 추가한다. (훅이 이미 커밋된 파일의 수정을 막는다)
- 아직 어떤 환경에도 적용되지 않은 파일만 고치거나 지우고 다시 만들 수 있다.
- 새 번호는 현재 가장 큰 버전 + 1 이다. 만들기 전에 폴더의 최신 번호를 확인한다.
- 참조하는 테이블이 먼저 만들어지는 순서로 번호를 매긴다. 서로 참조하는 순환 FK 는 한쪽을 FK 없이 만들고, 마지막에 `ALTER TABLE` 로 FK 를 붙인다.
- 엔티티와 SQL 의 컬럼명·타입·길이·제약이 1:1 로 같아야 한다. `ddl-auto: validate` 를 유지한다.
- 이미 데이터가 있는 테이블에 NOT NULL 컬럼을 추가할 때는 기본값이나 단계적 적용(컬럼 추가 → 채우기 → 제약 추가)을 쓴다.
- 만든 뒤에는 로컬 DB 에서 실제로 적용해 보고 로그에서 성공을 확인한다.
