# 문서 관리 규칙

문서 폴더 구조는 프로젝트의 `CLAUDE.md` 가 정한 대로 따른다. 정해진 게 없으면 아래를 기본으로 쓴다.

| 종류 | 위치 | 파일명 |
|---|---|---|
| 설계·기능 문서 | `docs/design/` | `{이슈번호}-{설명}.md` |
| 테스트 결과 문서 | `docs/test-results/` | 설계 문서와 같은 이름 |

## 설계·기능 문서에 꼭 넣을 것
- 배경 (왜 만들었는지)
- 구현 내용 (주요 클래스와 흐름)
- API 명세 (메서드, URL, 요청, 응답, **에러 케이스**)
- 설계 결정 (왜 이렇게 했는지, 고민한 다른 선택지)
- 검증 (어떻게 확인했는지)
- 남은 이슈
- `closes #이슈번호`

## 테스트 결과 문서에 꼭 넣을 것
- 정상 케이스 1개 이상, 에러 케이스 1개 이상
- 실행한 명령과 결과 숫자
- 비밀번호, 토큰, 개인정보는 적지 않는다.

## 유지 규칙
- 코드가 바뀌어 문서가 낡았으면 같이 고친다. 해결된 TODO 는 지우지 말고 ~~취소선~~ 뒤에 "해결됨"으로 남긴다.
- 확실하지 않은 내용을 단정해서 쓰지 않는다. 코드에서 확인한 것만 쓴다.
- 비공개 계획용 약칭(내부 PR 번호 등)을 문서에 쓰지 않는다. 실제 이슈 번호나 기능 이름을 쓴다.
