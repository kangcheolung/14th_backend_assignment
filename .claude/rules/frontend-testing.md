# 프론트 테스트 규칙

- Vitest(또는 프로젝트의 러너)와 Testing Library 를 쓴다.
- **사용자 관점**으로 테스트한다. `getByRole`, `getByLabelText`, `getByText` 로 요소를 찾고, 내부 상태나 구현 세부는 검증하지 않는다.
- 서버 호출은 MSW 나 mock 으로 대체한다. 실제 서버에 의존하지 않는다.
- 비동기 화면은 `findBy…`, `waitFor` 로 기다린다. `setTimeout` 으로 시간을 때우지 않는다.
- 시나리오: 정상 흐름, 에러 응답이 화면에 보이는지, 로딩과 빈 상태, 로그인 필요 화면의 이동
- 테스트마다 독립적으로 렌더링하고 상태를 공유하지 않는다.
- 테스트를 지우거나 약하게 바꿔서 통과시키지 않는다.
- 끝내기 전에 `npm test` (또는 프로젝트 명령) 와 `npm run build` 가 통과하는지 실제로 실행해서 확인한다.
