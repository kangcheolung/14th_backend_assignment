# React 컴포넌트 규칙

- 함수 컴포넌트와 TypeScript 를 쓴다. props 는 타입(`interface XxxProps`)으로 정의하고 `any` 를 쓰지 않는다.
- 컴포넌트 하나는 한 가지 일만 한다. 화면이 길어지면 의미 단위로 나눈다. 한 파일에 컴포넌트를 여러 개 두지 않는다.
- 상태는 그걸 쓰는 가장 가까운 컴포넌트에 둔다. 서버 데이터는 컴포넌트 상태가 아니라 데이터 패칭 라이브러리나 전용 훅으로 다룬다.
- 데이터가 있는 모든 화면은 **로딩, 에러, 빈 상태, 정상** 네 가지를 모두 그린다.
- 로그인이 필요한 화면은 인증 상태를 확인하고, 없으면 로그인 화면으로 보낸다.
- 목록 렌더링에는 안정적인 `key` (id) 를 쓴다. index 를 key 로 쓰지 않는다.
- 접근성: `img` 에 `alt`, 입력에 `label`, 버튼은 `<button>`, 클릭 가능한 `div` 를 만들지 않는다.
- `useEffect` 로 데이터를 가져오거나 파생 값을 계산하지 않는다. 필요한 경우 의존성 배열을 정확히 쓴다.
- 서버가 내려준 에러 메시지는 사용자에게 보여준다. 콘솔에만 찍고 넘기지 않는다.
- `console.log`, 주석 처리한 코드를 남기지 않는다.
