# 안전 규칙

## 절대 하지 않는 것
- `.env`, 키 파일, 비밀번호, 토큰을 읽어 출력하거나 커밋하거나 코드·설정에 하드코딩하지 않는다.
- `git push --force`, `main`/`develop` 직접 push, `git reset --hard`, `--no-verify` 를 쓰지 않는다.
- `rm -rf` 로 홈이나 루트를 지우지 않고, `DROP TABLE/DATABASE` 를 실행하지 않는다.
- 이미 적용된 마이그레이션 파일을 고치지 않는다. 새 버전 파일을 추가한다.
- 위 항목은 훅이 막는다. 훅이 막았다면 우회하지 말고 이유를 사용자에게 알린다.

## 먼저 확인받고 하는 것
- 파일·브랜치·데이터를 지우는 작업
- 외부에 보이거나 되돌리기 어려운 행동: push, 이슈·PR 생성, 메시지 전송, 배포, 릴리스
- 의존성 추가, 설정 파일(보안·CORS·권한) 변경

## 일하는 방식
- 요청한 범위 밖의 파일은 고치지 않는다. 필요해 보이면 제안만 한다.
- 모르는 것을 추측으로 채우지 않는다. 확인할 수 있으면 확인하고, 확인할 수 없으면 확인하지 못했다고 말한다.
- 수정한 뒤에는 실제로 반영됐는지 다시 확인하고 결과를 보고한다.
