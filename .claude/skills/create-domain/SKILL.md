# 도메인 골격 만들기

고정 템플릿을 쓰지 않는다. **프로젝트에 이미 있는 도메인을 보고 그대로 따라 만든다.**

## 절차
1. **기존 구조 파악**: 도메인 하나를 골라 읽는다. 패키지 구조, 네이밍, 공통 클래스(`BaseEntity`, 공통 응답, 공통 예외·`ErrorCode`), 서비스 분리 방식(Command/Query 여부), 변환기(converter) 사용 여부를 확인한다.
   - 기존 도메인이 없으면 `~/.claude/rules` 의 백엔드 규칙을 기준으로 하되, 어떤 구조로 만들지 먼저 제안하고 확인받는다.
2. **선택 항목 질문**: `scheduler`, `client`(외부 API), `event`, `enums` 가 필요한지 묻는다. 필요하다고 한 것만 만든다.
3. **만들 파일 목록을 보여주고 확인받는다.**
4. **생성**: entity, repository, service, controller, dto(request/response), 필요하면 converter. 새 클래스에는 규칙대로 역할을 적은 Javadoc 을 붙인다.
5. **연결**: `ErrorCode` 에 도메인 에러 코드를 추가한다. Flyway 같은 마이그레이션을 쓰는 프로젝트면 새 버전 파일이 필요하다고 안내한다.
6. **확인**: 컴파일(`./gradlew compileJava`)이 통과하는지 실행해서 확인한다.
7. **안내**: 엔티티 필드와 DTO 필드를 채울 차례라는 것, 테스트(`write-tests`)와 설계 문서(`design-doc`)가 남았다는 것을 알린다.

## 하지 않는 것
- 요청하지 않은 API 구현이나 비즈니스 로직을 채워 넣지 않는다. 골격만 만든다.
