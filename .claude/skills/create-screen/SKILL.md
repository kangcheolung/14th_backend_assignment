# 화면 만들기

## 절차
1. **기존 구조 파악**: 화면 하나를 골라 읽는다. 라우팅, 상태·서버 데이터 관리 방식, API 클라이언트, 스타일(Tailwind), 폴더 구조를 확인한다.
2. **요구 확인**: 화면이 보여줄 것과 동작을 정리한다. API 가 필요하면 명세(`docs/api-spec.md` 또는 컨트롤러)를 읽어서 요청·응답 필드를 확인한다. 모르는 필드는 추측하지 않고 묻는다.
3. **만들 파일 목록을 보여주고 확인받는다.** (페이지, 컴포넌트, API 함수, 타입, 라우트)
4. **생성**: `rules/react-components.md`, `api-client.md`, `styling-tailwind.md` 를 따른다.
   - 로딩, 에러, 빈 상태, 정상 상태를 모두 그린다.
   - 로그인이 필요한 화면은 인증 확인과 로그인 화면 이동을 넣는다.
   - 서버 에러 메시지를 화면에 보여준다.
   - 모바일 폭에서도 깨지지 않게 한다.
5. **확인**: `npm run build`(와 린트)가 통과하는지 실행해서 확인한다. 브라우저 도구가 있으면 개발 서버를 켜서 실제 화면도 본다. 화면을 직접 확인하지 못했다면 확인하지 못했다고 보고한다.
6. 화면 테스트(`write-tests`)나 E2E(`e2e-playwright`)가 필요하면 제안한다.

## 하지 않는 것
- 요청하지 않은 화면, 라이브러리, 전역 스타일을 추가하지 않는다. 새 라이브러리가 필요하면 이유를 말하고 확인받는다.
