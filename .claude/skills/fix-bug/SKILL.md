# 버그 고치기

## 절차
1. **증상 정리**: 기대한 동작, 실제 동작, 재현 절차를 짧게 정리한다. 부족하면 묻는다.
2. **재현**: 실패하는 테스트나 명령으로 먼저 재현한다. 재현하지 못하면 고치지 말고 알린다.
3. **원인 확인**: 코드를 읽고 로그를 보며 원인을 좁힌다. 추측으로 고치지 않는다. 원인을 한 문장으로 설명할 수 있어야 다음으로 간다.
4. **최소 수정**: 원인이 되는 곳만 고친다. 근처 코드를 같이 정리하지 않는다.
5. **재발 방지 테스트**: 수정 전에는 실패하고 수정 후에는 통과하는 테스트를 추가한다. (`write-tests` 규칙을 따른다)
6. **검증**: `verify` 스킬의 절차로 빌드와 전체 테스트가 통과하는지 확인한다.
7. **보고**: 원인, 수정 내용, 추가한 테스트, 확인한 결과(명령과 숫자)를 알린다.

## 참고
- 이슈나 브랜치가 없으면 `start-issue` 를 제안한다. 브랜치 이름은 `fix/{번호}-…` 다.
- 프로덕션 수정과 테스트 추가는 커밋을 나눈다. 커밋은 `commit-plan` 으로 확인받고 한다.
