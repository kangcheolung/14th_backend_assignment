# 하네스 점검

## 대상
- 전역: `~/.claude/CLAUDE.md`, `rules/`, `skills/`, `hooks/`, `settings.json`
- 프로젝트: `CLAUDE.md`, `.claude/rules/`, `.claude/skills/`, `.claude/settings.json`, `docs/`

## 점검 항목
| 항목 | 확인 방법 |
|---|---|
| 낡음 | 문서가 가리키는 파일·명령·패키지가 실제로 있는지 확인 |
| 충돌 | 서로 반대되는 규칙이 있는지 (예: 브랜치 이름, 커밋 형식) |
| 중복 | 같은 내용이 여러 파일에 있는지 |
| 모호 | "적절히", "필요하면"처럼 판단 기준이 없는 문장 |
| 길이 | `CLAUDE.md` 가 200줄을 넘는지, 규칙 파일이 너무 긴지 |
| 스킬 겹침 | `description` 이 비슷해 엉뚱한 스킬이 뽑힐 수 있는지 |
| 규칙 경로 | `paths:` 패턴이 실제 폴더 구조와 맞는지 |
| 훅 동작 | `python3 ~/.claude/hooks/tests/test_hooks.py` 를 실행해 통과하는지 |

## 절차
1. 대상 파일을 실제로 읽고 점검한다. 읽지 않은 파일에 대해 말하지 않는다.
2. 결과를 **높음 / 중간 / 낮음**으로 나눈 표로 보여준다. 항목마다 파일, 문제, 고칠 방향을 적는다.
3. 수정은 사용자가 고른 항목만, 승인 뒤에 한다.
