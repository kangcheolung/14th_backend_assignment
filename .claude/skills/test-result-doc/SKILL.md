# 테스트 결과 문서

## 절차
1. **실행**: 프로젝트의 테스트 명령(`./gradlew test` 등)을 실제로 돌려 결과 숫자와 실패 항목을 얻는다. 이미 돌린 결과가 있으면 그것을 쓰되 실행 시각을 적는다.
2. **수동 검증 기록 수집**: Swagger 나 HTTP 로 직접 호출한 기록이 있으면 요청·응답을 함께 정리한다. 없으면 없다고 쓴다. 지어내지 않는다.
3. **문서 작성**: `docs/test-results/{이슈번호}-{설명}.md` (설계 문서와 같은 이름)
   - 검증 정보: 브랜치, 커밋, 실행 일시, 환경
   - 정상 케이스 1개 이상 (요청, 기대 결과, 실제 결과)
   - 에러 케이스 1개 이상 (요청, 기대 에러 코드, 실제 결과)
   - 자동 테스트 결과: 명령과 `N passed, M failed`
   - 전체 회귀 결과
   - 한계와 확인하지 못한 것
4. 비밀번호, 토큰, 개인정보는 적지 않는다.
5. 파일만 쓰고 커밋하지 않는다. (`commit-plan`)
