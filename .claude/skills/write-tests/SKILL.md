# 테스트 작성

## 절차
1. **대상 파악**: 지정이 없으면 `git diff` 와 최근 커밋에서 테스트가 필요한 로직(서비스, 검증, 권한)을 찾는다.
2. **기존 패턴 확인**: 같은 종류의 기존 테스트를 읽는다. 백엔드는 `rules/testing-backend.md`, 프론트는 `rules/frontend-testing.md` 를 따른다.
3. **시나리오 목록을 먼저 보여준다.** 아래 세 가지를 모두 갖춘다.
   - 정상 케이스
   - 예외 케이스 (없는 대상, 권한 없음, 검증 실패, 중복)
   - 경계 케이스 (0, 빈 값, 최대 길이, 마지막 페이지)
4. **작성**: 단위 테스트를 우선한다. DB 나 전체 흐름이 꼭 필요할 때만 `@DataJpaTest`, 통합 테스트를 쓴다.
5. **실행**: `./gradlew test --tests '<대상>'` 또는 `npm test` 로 실제로 돌린다.
6. **실패 처리**: 원인이 테스트 오류인지 코드 버그인지 가른다. 테스트를 지우거나 단언을 약하게 만들어서 통과시키지 않는다. 코드 버그면 알리고 고칠지 묻는다.
7. **보고**: 추가한 시나리오 목록과 결과 숫자(`N passed, M failed`)를 알린다.

## 참고
- 프로덕션 코드와 테스트 코드는 커밋을 나눈다. (`commit-plan`)
